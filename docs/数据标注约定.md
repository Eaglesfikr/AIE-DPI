# 数据标注约定（阶段 0 定稿）

交付要求：**自建标注数据集**（PCAP，自行整理并提交）。本文件定义组织与标注格式，保证一致、可复现。

## 1. 目录组织

```
data/
├── raw/                  # 采集的原始 PCAP（未标注、按批次）
│   └── batch_YYYYMMDD/
├── labeled/              # 标注数据集（交付结构）
│   ├── manifest.csv      # 总清单（一行一个会话/样本）
│   ├── social/           # 场景一：社交应用分类的标注 pcap（可切片到会话级）
│   │   ├── wechat/
│   │   ├── whatsapp/
│   │   ├── telegram/
│   │   └── non_social/   # 噪声/对照样本（网页、视频等）
│   └── ...
└── processed/            # 中间结果（会话 JSON、特征 CSV）不入库
```

## 2. 标签 schema（manifest.csv）

| 列 | 必填 | 说明 |
|---|---|---|
| `session_id` | ✔ | 唯一会话 ID（`<app>_<batch>_<seq>`） |
| `file` | ✔ | pcap 相对路径 |
| `app` | ✔ | 应用标签，如 `wechat` / `whatsapp` / `non_social` |
| `platform` | ✔ | `android` \| `ios` \| `pc` |
| `behavior` | 可选 | 行为标签（阶段 2 用）：`voice_call` / `video_call` / `text_chat` / `post_text` 等 |
| `start_ts` | ✔ | 会话开始时间戳（epoch，秒或毫秒，需在文档说明单位） |
| `end_ts` | ✔ | 会话结束时间戳 |
| `protocol` | 可选 | 主导协议：`tls13` / `tls12` / `quic` / `plain` |
| `remark` | 可选 | 采集方式、干扰因素等备注 |

时间戳单位必须统一并在 `README` 注明（默认 **微秒**，与 pcap capture timestamp 一致）。

## 3. 采集与生成建议

- **场景一社交应用分类**目标：每类 ≥ 数十次会话，混合 Android / iOS / PC 三平台（满足跨平台要求）。
- 采集方式：
  1. **真机抓包**：手机连共享热点，主机侧 tcpdump/Wireshark 抓包，操作时固定时间窗标记行为。
  2. **可控触发**：录制操作（发消息、打电话、刷信息流），用操作日志与抓包时间轴对齐打标签。
- **噪声控制**：`non_social` 类需包含网页浏览、在线视频、系统更新等干扰流量（评估假阳率用）。
- 隐私与合规：自建数据注意脱敏，禁止上交含个人信息/账号内容的流量。

## 4. 质量要求（提交前自检）

- [ ] manifest.csv 字段完整、单位一致
- [ ] 每类样本数与平台覆盖满足指标测评需要
- [ ] 会话切片干净：单会话内尽量减少跨应用混合流
- [ ] 记录采集环境（设备、OS 版本、应用版本、网络类型）到 `docs/数据集说明.md`

## 5. 会话划分口径（与 parser 对齐）

- TCP：按五元组 + TCP 连接生命周期（SYN→FIN/RST）。
- UDP/QUIC：按五元组 + 空闲超时（默认 **120s** 无包则断流，可在配置调整）。
- 方向：以源/目的 IP 归属标记 客户端↔服务器（C↔S），特征方向比均按 C→S / S→C 计算。

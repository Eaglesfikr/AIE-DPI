## 1. 目标

跑通「PCAP → 会话重组 → 特征 → 智能分析 → 规则文件 → DPI 引擎 → 指标测评」的最小闭环，
实现**社交应用vs非社交应用分类**（场景一），并产出：
1. 特征挖掘工具（含规则生成能力）
2. 配套 DPI 规则引擎（加载规则、输出识别结果）
3. 可解释规则文件（人工可修正，可用率 ≥ 90% 的载体）
4. 会话级分类指标：召回率 ≥ 98%、准确率 ≥ 95%、精确率 ≥ 95%、假阳率 ≤ 5%

## 3. 处理链路总览

```
Automatic/<app>/*.pcapng
   │  PcapReader.read_packets（scapy 逐包流式读取，防大文件占满内存）
   ▼
   会话重组 reassemble（五元组分组 + 排序去重 + 空闲超时断流）
   ▼  sessions.json
   特征提取（基础 + 高级）→ features.csv
   ▼
   特征分析（训练可解释模型 → 特征重要性）
   ▼
   规则生成（重要特征 → 阈值规则 → rules/social.yaml）
   ▼
   engine/dpi_engine 加载规则 → 匹配 → DetectionResult
   ▼
   指标测评（train/test 按 pcap 文件切分）
```

## 4. 模块实施明细

### 4.1 任务一 · 1.1 解析与会话重组（`src/feature_miner/parser/`）

| 子项 | 实现要点 | 落点文件 |
|---|---|---|
| PCAP 读取 | `RawPcapReader` 逐包流式；统一包 dict 字段（ts/src/dst/proto/payload） | `pcap_reader.py` |
| TCP 重组 | 五元组分组；按 seq 排序处理乱序；seq 相同判重传去重 | `reassembler.py`（新增） |
| UDP/QUIC 会话 | 五元组 + 空闲超时 120s 断流（config 可调） | `reassembler.py` |
| TLS 指纹 | ClientHello/ServerHello 解析：SNI、ALPN、cipher suites、JA3/JA3S（先 TCP TLS；QUIC 视样本需要） | `tls.py` |
| 方向判定 | 先 SYN（TCP）/先发握手者（UDP）=客户端；TTL/DNS 兜底 | `reassembler.py` |

里程碑 **M1**：`data/processed/sessions.json` 可稳定产出，单元测试覆盖乱序/重传/断流。

### 4.2 任务一 · 1.2/1.3 特征提取（`src/feature_miner/features/`）

特征清单初稿（命名 `维度.子维度.统计`）：

- **基础协议信息**：`tls.version`、`tls.sni`、`tls.alpn`、`tls.cipher`、`tls.ja3`、`tls.ja3s`、`flow.port_server`、`flow.proto`
- **流统计**：`flow.pkt.c2s/s2c`、`flow.bytes.c2s/s2c`、`flow.pkt_len.mean/std/min/max`、`flow.dur`、`flow.byte_ratio`、`flow.ttl.*`
- **流段统计**：按 5s 时间窗切片，`flow.slice.N.pkt_len.mean`、`flow.slice.N.bytes`（N=1..k，k 自适应）
- **时序行为**：`flow.iat.mean/std/med/p90`、`flow.burst.count/len.mean`、`flow.pkt_rate`
- **高级维度**：前 N 包长度序列 `flow.win.headN_len`、C→S 包长直方图 `flow.hist.c2s.len/bytes`、周期节奏 `flow.period.fft_top`、DNS 关联 `dns.n_domains`、证书信息 `tls.cert.*`（可解析时）

实现：
- `base.py`（流统计/流段/时序）、`advanced.py`（序列/直方图/周期）填充 `feature_store.py`
- 统一由 `session → FeatureStore`，输出 `features.csv`
- 特征有效率口径：先按「样本中非 NaN/非常量的特征占比」做初筛（≥80% 目标），分析阶段再按区分度确认

里程碑 **M2**：`features.csv` 产出；每类 200+ 会话样本量。

### 4.3 任务一 · 1.4 特征智能分析（`src/feature_miner/analyzer/select.py`）

- 输入 `features.csv` + manifest 标签。
- **可解释优先**：先 `单变量 AUC / 信息增益` 快筛 → `XGBoost` 特征增益/SHAP 复核。
- 输出 `FeatureSummary`：候选特征清单（含阈值方向）+ 识别方案（如「SNI∈{facebook…} ⇒ facebook；否则流统计阈值分类」）。
- 有效性自评：选出的特征在简单阈值/单规则上的会话级验证准确率，逐步逼近 80%~90%。

### 4.4 任务一 · 1.5 规则生成（`src/feature_miner/rule_gen/generator.py`）

- 规则文件 schema **v0**（YAML，人工可读/可改），单文件 `rules/social.yaml`：

```yaml
schema_version: v0
target: social_classification
rules:
  - rule_id: r001
    priority: 10        # 数值小=越优先评估
    cost: low           # low(首包/握手) | mid(会话统计) | high(时序/长窗口)
    conditions:
      - { feature: tls.sni, op: "in", value: [ "facebook.com", "*.facebook.com" ] }
    conclusion: { app: facebook, confidence: 0.98 }
  - rule_id: r002
    priority: 20
    cost: mid
    conditions:
      - { feature: flow.pkt_len.mean, op: "gte", value: 900 }
      - { feature: flow.byte_ratio,   op: in_range, value: [0.3, 0.7] }
    conclusion: { app: <social_group>, confidence: 0.90 }
```

- 规则生成策略：从 1.4 选出的高区分特征自动生成「特征→阈值」规则（决策树路径抽规则），人可修正。
- 规则覆盖率自检：每条规则在训练集上的覆盖/命中分布。

### 4.5 任务二 · 2.1 DPI 引擎（`engine/dpi_engine/`）

- `loader.py`：YAML 读取 + schema 校验 + 按 priority/cost 排序编译。
- `matcher.py`：分层匹配 —— 低代价规则优先评估，命中即短路；未命中降级到 mid/high 组。
- `result.py`：`DetectionResult`（已有骨架）。
- `cli.py`：`--rules rules/social.yaml --input <pcap或sessions.json> --format auto`。

里程碑 **M3**：引擎加载 `rules/social.yaml` 输出结果。

### 4.6 任务二 · 2.2 指标测评

- **切分**：按 pcap 文件而非按会话切分 train/test（防同文件内会话泄漏）；建议 7:3。
- **指标（会话级）**：召回率、准确率、精确率、假阳率；对照类=非社交组。
- **报告**：`docs/阶段1测试报告.md`（混淆矩阵 + 每类指标 + 未命中样例分析）。

里程碑 **M4**：四项指标达标（≥98/95/95；FPR≤5%）；不达标 → 回迭代 1.4/1.5。

## 5. 依赖的现实约束

1. **MPAF 无平台标注**（大概率 Android 抓取）：跨平台适应性（Android/iOS/PC）在阶段 3 用自抓包补充验证；阶段 1 先把方法链路打通。manifest 的 `platform` 列先记 `unknown`。
2. **MPAF 无行为标注**：发文字贴/IM 精细行为不在阶段 1 范围（需自抓包，见阶段 2）。
3. **大 pcap 内存**：流式读取 + 会话级聚合，避免 `rdpcap` 整包载入。
4. **QUIC/TLS1.3**：先实现 TCP TLS 指纹；QUIC 解析视 facebook 等样本实际占比推进（贴合赛题加密场景）。
